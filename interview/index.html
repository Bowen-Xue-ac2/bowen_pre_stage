第二类 · 01

积分商城的实时竞价与 Agent

学生一周最多用 100 积分竞拍两场活动的限量权益，优先周五，也接受周三。人工与受托 Agent 均可出价。现有商城支持查积分、看商品和兑换。

一轮竞价怎样进行？ 假设周三活动只剩一张入场券，本轮约定截止时有效报价最高者得。甲出 12 分、乙出 18 分，两笔都被受理。截止前名额仍未确定；若无人再出价，截止后乙中选，甲的预留积分释放。

提醒建议，学生确认授权内代投
模块职责
M / A学生手动输入 / Agent 建议或代投
U统一入口：身份、授权、轮次、截止时间
P预算节奏：判断当前参与程度
L积分账本：原子查额度、预留、结算、释放
E / Q竞价处理 / 按稳定操作 ID 回查结果
V页面区分建议、已受理、已成交

机会与出价　周三、周五各有一轮。每笔报价写明轮次、所竞拍的权益、替谁出价和多少整数积分。系统用出价 ID 将受理回执和最终结果对应到这一笔。

预算节奏　100 分要覆盖整周。先看后面还有哪些场次、学生更想去哪场，再安排每个时点预计累计花多少。到周三，把实际支出与计划对照，决定后续是否少参加几轮。每轮具体报多少分另行判断。

  1. 01

    接入 Agent。选择模式与模块，画出人工出价和 Agent 共用统一业务入口的职责图。

  2. 02

    算法与 Agent 共存。周三计划累计花 30 分，实际花 40 分，Agent 又建议 25 分机会。谁怎样决定最终准入？

  3. 03

    校园预算规则。总预算 100 分，未消费或预留；周五硬保留 60 分，周三出现 45 分机会。写规则并判断是否参与。

  4. 04

    Runtime 并发。两个窗口同时提交独立出价，第一笔已预留但回执迟到。画状态流程，避免重复扣分和超额承诺。

积分如何流转　出价时可先预留积分（pending），这部分余额暂时不能再用。中选后按规则结算（post），未中或预留到期则释放（void 或到期释放）。结算、释放记录均关联原预留。

回执迟到怎么办　同一笔出价重试沿用原 ID，方便查到之前的处理结果。可参考现有报名流程：结果不明时先查本人的记录。后台任务提交结果时还会核对用户、租约 token 和有效期。
