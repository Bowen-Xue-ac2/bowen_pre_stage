第二类 · 01

积分商城的实时竞价与 Agent

学生一周最多用 100 积分竞拍两场活动的限量权益，优先周五，也接受周三。人工与受托 Agent 均可提交意向。现有商城仅查询积分、商品和兑换；竞价为本题设想。

提醒建议，学生确认授权内代投
模块职责
M / A学生手动输入 / Agent 建议或代投
U统一入口：身份、授权、轮次、截止时间
P预算节奏：判断当前参与程度
L积分账本：原子查额度、预留、结算、释放
E / Q竞价处理 / 按稳定操作 ID 回查结果
V页面区分建议、已受理、已成交

机会与响应：统一轮次、权益、委托主体、整数积分、截止时间、逻辑出价 ID。

预算节奏：预测机会 → 分配预算 → 比较累计实际与计划 → 调整后续参与；不直接计算报价。

账务：pending 预留；post 结算；void / 到期释放。重试同一事件复用 ID，不同阶段记录相互关联。

现有参考：报名 unknown / executing 先回查；后台结果提交时核验用户、租约 token 和未过期条件。

  3. 03

    校园预算规则。总预算 100 分，未消费或预留；周五硬保留 60 分，周三出现 45 分机会。写规则并判断是否参与。

  4. 04

    Runtime 并发。两个窗口同时提交独立出价，第一笔已预留但回执迟到。画状态流程，避免重复扣分和超额承诺。
